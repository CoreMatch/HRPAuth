# HRPAuth

[中文说明](README.zh-CN.md)

HRPAuth is a general-purpose authentication core service and the OAuth2 authorization center of the HA ecosystem: accounts, login, and multi-factor security for your users, plus OAuth2 issuance for the services around it.

> **Scope note:** The Yggdrasil protocol and skin/texture features are **not** part of this repository. They were split out on 2026-10-06 and now live in dedicated microservices: [HRPAuth-Yggdrasil-API](https://github.com/CoreMatch/HRPAuth-Yggdrasil-API), [HASkinLib](https://github.com/CoreMatch/HASkinLib) and [HASkinProxy](https://github.com/CoreMatch/HASkinProxy).

## Quick Start

### 1. Prerequisites

- Go 1.26 or higher
- MySQL
- Redis
- An SMTP server (for verification emails)

### 2. Clone and run

```bash
git clone https://github.com/CoreMatch/HRPAuth.git
cd HRPAuth

# First run: config.yaml is generated automatically (configuration only — no keys or certificates are generated)
go run main.go
```

### 3. Configure and restart

Edit the required fields in the generated `config.yaml` (see [Configuration](#configuration)), then build and run:

```bash
go build -o HRPAuth
./HRPAuth
```

## Configuration

Fields you **must** adjust before deploying:

| Field | Purpose |
|---|---|
| `database` | MySQL connection (host, database name, user, password) |
| `redis` | Redis connection |
| `smtp` | Mail server for verification emails |
| `server.port` | HTTP listen port |
| `callback.url` | Public URL of this service |
| `frontend.url` | URL of the web frontend (HRPAuth-WebUI) |

All other fields have working defaults, and the configuration schema is migrated automatically on startup (current version: **11**).

### Complete configuration reference

Example `config.yaml`:

```yaml
version: "11"
site:
  name: "HRPAuth"
  implementation: "HRPAuth"
  version: "1.0.0"
server:
  port: ":8080"
  cors_origin: "*"
callback:
  url: "https://backend.auth.example.com/"
frontend:
  url: "https://auth.example.com/"
database:
  host: "localhost"
  db_name: "hrpauth"
  user: "root"
  password: ""
  charset: "utf8mb4"
  retry_interval_sec: 3
  max_retries: 5
  next_round_delay_min: 5
verification_code:
  code_ttl: 600
  storage_dir: "./cache/verification_codes"
redis:
  host: "localhost"
  port: 6379
  password: ""
  db: 0
  prefix: "hrpauth_"
smtp:
  host: "smtp.example.com"
  port: 587
  username: ""
  password: ""
  encryption: "tls"
  from_email: "noreply@example.com"
  from_name: "HRPAuth"
manage:
  token: "<auto-generated on first startup>"
security:
  password_cost: 10              # bcrypt cost for native and reset-updated HRPAuth passwords
  rate_limit_max_attempts: 10    # Max login failure count
  rate_limit_window_sec: 600     # Login failure window (seconds)
  enable_captcha: true           # Enable graphical captcha (mandatory validation for /register)
  captcha_ttl: 300               # Captcha TTL (seconds), stored in Redis
webauthn:
  rp_display_name: ""            # Defaults to site.name
  rp_id: ""                      # Defaults to the domain derived from rp_origins
  rp_origins: []                 # Defaults to the callback/frontend URLs
  session_ttl_sec: 300
core_api:
  base_url: "http://localhost:2778"
  client_id: "hrpauth-internal-super"
  client_secret: "<auto-generated>"
yggdrasil_api:
  base_url: "http://localhost:2779"
sdk_packages:
  storage_dir: "./data/sdk_packages"
  max_package_size: 20971520
  max_packages: 128
```

Schema versions and auto-migration (chain-linked, one migration function per
version, see [`config/migrations.go`](config/migrations.go)):

| Version | Changes |
|---------|---------|
| `1.0` | Initial YAML configuration (`memcache` captcha, no redis) |
| `2` | Added `redis`; renamed `memcache` to `verification_code` |
| `3` | Moved `security` fields (including captcha) from `yggdrasil.security` to the top-level `security`; added `manage.token`; default `redis.prefix` is `hrpauth_` |
| `4` | Added `oauth2` section for site-side OAuth2 authorization |
| `5` | Added `yggdrasil.security.max_texture_file_size` for texture upload file size limit (default 512000) |
| `6` | Added top-level `storage` section with `orphan_file_expiry_days` (default 7) |
| `7` | Added `oauth2.super_client_extra_scopes` for database scope delegation |
| `8` | Decouple yggdrasil: introduced `core_api` and `yggdrasil_api` sections for service-to-service communication |
| `9` | Added top-level `sdk_packages` section for compile-time SDK aggregation |
| `10` | Removed static `internal_key` from `core_api` and `yggdrasil_api`; internal service authentication now uses dynamic temporary keys via OAuth2 |
| `11` (Current) | Added database connection retry settings: `database.retry_interval_sec` (default 3), `database.max_retries` (default 5), `database.next_round_delay_min` (default 5) |

Migration behavior: the original file is backed up as
`config.yaml.bak.<old_version>` before migration (one backup per version); a
configuration newer than the program warns but starts without rewriting; a
failed migration terminates startup and leaves the original file untouched;
writes are atomic (temporary file + rename).

Field descriptions:

| Section | Field | Type | Default | Description |
|-------|-------|------|---------|-------------|
| top-level | `version` | string | — | Configuration schema version (current `"11"`) |
| `site` | `name` / `implementation` / `version` | string | `"HRPAuth"` / `"HRPAuth"` / `"1.0.0"` | Service identity; appears in `GET /status` and Yggdrasil `meta.serverName` |
| `server` | `port` | string | `":8080"` | Listening port (must include colon) |
| `server` | `cors_origin` | string | `"*"` | CORS allowed Origin |
| `callback` | `url` | string | — | Backend callback address (appears as `site.url` in the `GET /` status response) |
| `frontend` | `url` | string | — | Frontend page address |
| `database` | `host` / `db_name` / `user` / `password` | string | — | MySQL connection |
| `database` | `charset` | string | — | Character set, recommended `utf8mb4` |
| `database` | `retry_interval_sec` / `max_retries` / `next_round_delay_min` | int | `3` / `5` / `5` | Connection retry interval, max retries, delay before the next retry round (`0` disables further rounds) |
| `verification_code` | `code_ttl` | int | `600` | Verification code TTL (seconds) |
| `verification_code` | `storage_dir` | string | `"./cache/verification_codes"` | Directory for verification code JSON files |
| `redis` | `host` / `port` / `password` / `db` / `prefix` | — | `"localhost"` / `6379` / `""` / `0` / `"hrpauth_"` | Redis connection and key namespace |
| `smtp` | `host` / `port` / `username` / `password` | — | — | SMTP server |
| `smtp` | `encryption` | string | — | `"tls"` / `"starttls"` / `"none"` |
| `smtp` | `from_email` / `from_name` | string | — | Sender address and display name |
| `security` | `password_cost` | int | `10` | bcrypt cost for newly generated or reset-updated passwords |
| `security` | `rate_limit_max_attempts` / `rate_limit_window_sec` | int | `10` / `600` | Login failure limit and window |
| `security` | `enable_captcha` | bool | `true` | Graphical captcha (mandatory validation for `/register`) |
| `security` | `captcha_ttl` | int | `300` | Captcha TTL in Redis (seconds) |
| `webauthn` | `rp_display_name` | string | `site.name` | Relying party display name |
| `webauthn` | `rp_id` | string | derived from `rp_origins` | Relying party ID (domain) |
| `webauthn` | `rp_origins` | array | derived from callback/frontend URLs | Allowed origins for WebAuthn ceremonies |
| `webauthn` | `session_ttl_sec` | int | `300` | WebAuthn ceremony session TTL (seconds) |
| `oauth2` | `issuer` | string | `callback.url` | OAuth2 issuer metadata base URL |
| `oauth2` | `authorization_code_ttl_sec` / `access_token_ttl_sec` / `refresh_token_ttl_sec` | int | `300` / `3600` / `2592000` | Token TTLs |
| `oauth2` | `super_client_id` / `super_client_secret` | string | `hrpauth-internal-super` / generated | Built-in low-friction service client |
| `oauth2` | `super_client_extra_scopes` | array | `[]` | Additional scopes for the built-in super client; only `db.*` scopes are accepted, others silently ignored |
| `oauth2` | `public_client_id` / `public_redirect_uris` | — | `hrpauth-webui` / `["<frontend>/oauth/callback"]` | Built-in public client for the first-party WebUI |
| `manage` | `token` | string | auto-generated | **Legacy Manage Token (M-T)**, kept only for backward compatibility; do not use in new integrations |
| `core_api` | `base_url` / `client_id` / `client_secret` | string | — | HRPAuth Core service-to-service calls (for satellites such as HRPAuth-Yggdrasil-API) |
| `yggdrasil_api` | `base_url` | string | — | Base URL of the HRPAuth-Yggdrasil-API service (for HRPAuth Core) |
| `sdk_packages` | `storage_dir` / `max_package_size` / `max_packages` | — | `"./data/sdk_packages"` / `20971520` / `128` | Compile-time SDK package store |

Notes:

- First-party WebUI login uses `authorization_code + PKCE`; service-to-service
  integration uses `client_credentials` with the built-in super client or an
  independent service client.
- Internal callback authentication uses dynamic temporary keys issued via
  `POST /services/auth-key`, not static configuration values.
- The OAuth2 built-in super client secret carries the main service-to-service
  power; protect it at the same level as the historical M-T.
- During BlessingSkin import, bcrypt hashes may be copied directly while
  non-bcrypt sources are converted into the fixed marker
  `BS2HA$RESET_REQUIRED` and must use password reset later.
- After modifying `config.yaml`, the **service must be restarted** to take
  effect (no hot reloading).

## Database migrations

Database schema is managed by SQL migrations
([golang-migrate](https://github.com/golang-migrate/migrate) format in
`database/migrations/`); `AutoMigrate` is **not** executed at startup.

- Entry point: `go run ./cmd/migrate ...` from the repository root (reuses the
  `database.*` settings of `config.yaml`).
- `000001_baseline` is the squashed core schema (`users`, `oauth2_clients`,
  `oauth2_authorization_codes`, `oauth2_access_tokens`,
  `oauth2_refresh_tokens`, `deleted_accounts`, `webauthn_credentials`). The
  historical steps `000002`–`000012` were squashed into the baseline on
  2026-10-14 (`b8a745c`). Minecraft-specific tables live in
  HRPAuth-Yggdrasil-API (`000001_init`).

```bash
go run ./cmd/migrate version   # current migration version and dirty state
go run ./cmd/migrate status    # same as version
go run ./cmd/migrate up        # apply all unapplied migrations
go run ./cmd/migrate up 1      # apply only N steps
go run ./cmd/migrate down      # rollback 1 step (down N for N steps)
go run ./cmd/migrate force 1   # mark the version without executing SQL
```

For a brand-new database run `go run ./cmd/migrate up`, then verify with
`status`. Rules: application startup never modifies tables; all schema
changes land through `database/migrations/`; when modifying GORM models,
evaluate whether a new migration is required.

## Deployment

### Single binary

```bash
./build.sh   # = go build -o ./build/HRPAuth
```

Pre-built binaries for six platforms are kept under [`build/`](build): darwin / linux / windows × amd64 / arm64.

### Container image

A multi-stage [Dockerfile](Dockerfile) is provided:

```bash
docker build -t hrpauth .
```

The image runs the same binary as a non-root user and exposes port `2778`. The [entrypoint](docker-entrypoint.sh) can render a configuration template from environment variables before startup (`CONFIG_TEMPLATE` / `RENDERED_CONFIG`).

### Platform orchestration (Compose)

HRPAuth is the core of the HA platform, but in production it runs as one service among many. The whole stack is orchestrated by a Compose template kept in [HA-Services-Deployer/deploy/docker-compose.yml](https://github.com/CoreMatch/HA-Services-Deployer/blob/main/deploy/docker-compose.yml), which builds every service image and wires them together:

```bash
git clone https://github.com/CoreMatch/HA-Services-Deployer.git
cd HA-Services-Deployer/deploy
cp .env.example .env   # database / Redis addresses, OAuth clients, keys, upstream URLs
docker compose up -d --build
```

| Service | Image | Port | Role |
|---|---|---|---|
| **HRPAuth** | `ha/hrpauth` | 2778 | Account and OAuth2 authorization core |
| HRPAuth-Yggdrasil-API | `ha/hrpauth-yggdrasil-api` | 2770 | Yggdrasil protocol provider |
| HASkinLib | `ha/haskinlib` | 2701 | Texture upload, storage and preview |
| HASkinProxy | `ha/haskinproxy` | 2702 | Skin service proxy for CustomSkinLoader clients |
| WinnerProxy | `ha/winnerproxy` | 2777 | Yggdrasil request routing proxy |
| HA-WebUI-SDKHandler | `ha/ha-webui-sdkhandler` | 2704 / 2705 | WebUI SDK aggregation and compilation |
| MatchCoreArena-Server | `ha/mca-server` | 9178 | Match core service |
| HA-Services-Deployer | `ha/ha-services-deployer` | 18080 | Manifest-driven deployment backend |
| HA-Services-MaintenanceView | `ha/ha-services-maintenance-view` | 18081 | Operations interface |

How the orchestration is wired:

- MySQL and Redis are **not** started by the stack; the services reach external instances through the `DB_*` / `REDIS_*` variables in `.env`.
- Each service's `config.yaml` is rendered from a template in `deploy/config/` at container startup, so database addresses, upstream URLs and secrets are all driven by `.env`.
- Inter-service calls use container names (for example `http://hrpauth:2778`), so no fixed host addresses are baked into the images.

## Features

- Registration, login and logout with email verification
- Captcha protection
- TOTP two-factor authentication
- WebAuthn / passkey login and second factor
- Email-based second factor
- Recovery keys
- Username and email changes
- Account deletion
